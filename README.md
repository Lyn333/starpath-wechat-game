# 森林寻径（Forest Trail）

> 一款面向移动端的**顺序路径连线谜题游戏**。玩家从 1 号路标出发，在不重复、不斜走、不穿越障碍的前提下，按数字顺序走遍整张棋盘。

森林寻径以微信小游戏的触摸体验为设计目标，同时提供基于浏览器的开发与验收版本。当前网页端采用天空蓝、白云、奶油棋盘、蘑菇红外框与亮绿色路径的轻量平台冒险视觉风格；游戏核心使用 Babylon.js 渲染，页面逻辑由 React 和 TypeScript 驱动。

## 玩法说明

每道题由正方形格点、数字路标和障碍边界组成。路径必须从 **1 号路标**起步，并以连续的上下左右移动连接后续数字。游戏引擎会实时拒绝违反规则的动作，因此玩家可以专注于规划路线。

| 规则 | 说明 |
|---|---|
| 起点 | 必须从 1 号路标开始。 |
| 移动方式 | 只能向上、下、左、右移动；不允许斜向移动。 |
| 数字顺序 | 必须依次经过 2、3、4……等后续路标，不能跳号。 |
| 障碍边界 | 路径不可穿越倒木、灌木等以边界形式呈现的障碍。 |
| 格子复用 | 已走过的格子不可再次经过；回到紧邻的上一步会自动回退。 |
| 过关条件 | 按顺序到达全部路标，并让路径覆盖棋盘的每一个格子。 |

在网页端可通过鼠标拖动或触摸滑动绘制路径。棋盘下方提供以下操作：

| 控件 | 用途 |
|---|---|
| **撤回** | 移除最后一步路径；完成状态下不可撤回。 |
| **清空** | 清除当前整条路径，并回到 1 号路标开始状态。 |
| **简单 / 中等 / 困难** | 切换难度分类，并随机进入该分类的一道未完成题。 |
| **6×6 / 8×8 / 10×10 / 12×12** | 切换棋盘尺寸，并随机进入当前难度下的对应题目。 |

首次访问时，游戏会显示三步新手引导，分别介绍起点、正交连线与撤回/清空操作。完成或跳过后会写入浏览器本地记录，不会重复弹出。

## 游戏功能

### 单棋盘移动端界面

主界面不会展示冗长的关卡目录，而是聚焦于一张当前可玩的棋盘。顶部状态栏显示当前难度、棋盘尺寸、用时与积分；底部控制区由棋盘实际下缘统一锚定，棋盘、操作栏、难度行和尺寸行维持一致的 8px 垂直节奏。

### 2,400 道首发关卡与随机抽题

首发题库按四种尺寸和三档难度组织。每种尺寸包含 Easy 300 道、Medium 200 道与 Hard 100 道，合计 600 道；四种尺寸合计 **2,400 道**。

| 棋盘尺寸 | 简单 | 中等 | 困难 | 小计 |
|---|---:|---:|---:|---:|
| 6×6 | 300 | 200 | 100 | 600 |
| 8×8 | 300 | 200 | 100 | 600 |
| 10×10 | 300 | 200 | 100 | 600 |
| 12×12 | 300 | 200 | 100 | 600 |
| **合计** | **1,200** | **800** | **400** | **2,400** |

题目在每个“尺寸 × 难度”分类内随机排列，并优先抽取未完成的首发题。分类内所有首发题均完成后，系统会按新 seed 生成续关题，避免与该分类现有题目重复。玩家完成进度和续关信息保存在浏览器 `localStorage` 中。

### 通关反馈与续题

成功通关后，界面会显示用时和积分。玩家可以选择“再走一次”，或进入同分类的随机下一题；当首发题耗尽时，按钮会切换为“生成新谜题”。

### 无障碍与视觉设计

难度按钮同时保留中文文字标签与原创 CSS 图标：简单为蘑菇、中等为砖块、困难为旗帜。核心交互控件具有可访问名称，棋盘 Canvas 使用明确的辅助说明标签。移动端背景包括轻量白云装饰，数字使用微软雅黑字体栈并在格子中水平、垂直居中。

## 快速开始

### 环境要求

| 工具 | 建议版本 |
|---|---|
| Node.js | 20 或更高版本；推荐 Node.js 22 |
| pnpm | 10 或更高版本 |
| 浏览器 | 支持 WebGL 2 的现代 Chrome、Edge、Safari 或 Firefox |

### 安装与启动

```bash
git clone https://github.com/Lyn333/starpath-wechat-game.git
cd starpath-wechat-game

# 如未安装 pnpm，可启用 Corepack
corepack enable

pnpm install
pnpm dev
```

开发服务默认运行在 `http://localhost:3000`。打开该地址即可进入游戏首页。

> 若浏览器显示 WebGL 不可用，请确认硬件加速已启用，并使用支持 WebGL 2 的现代浏览器。Babylon.js 棋盘渲染依赖可用的图形上下文。

## 验收与演示入口

以下参数便于在开发环境中快速复核指定体验。将其附加到本地地址或部署地址之后即可使用。

| 地址参数 | 用途 |
|---|---|
| `/?onboarding=1` | 强制显示三步新手引导，适合验收首次使用体验。 |
| `/?demo=1` | 进入 6×6 自动演示。 |
| `/?demo=8` | 进入 8×8 自动演示。 |
| `/?demo=10` | 进入 10×10 自动演示。 |
| `/?demo=12` | 进入 12×12 自动演示。 |
| `?demoSpeed=fast` | 与演示参数组合使用，以更快的节奏播放路径，例如 `/?demo=12&demoSpeed=fast`。 |
| `/editor` | 内容管理员使用的关卡编辑器；需要登录且具备管理员角色。 |

建议以 **390×844** 或相近的竖屏视口进行微信小程序式界面验收，重点检查棋盘完整可见、操作栏与两行选择器的间距、引导遮罩和按钮触达区域。

## 关卡与进度机制

### 关卡模型

一题关卡包含棋盘尺寸、数字路标、墙体/障碍、完整解法路径和元数据。共享校验逻辑会保证：

1. 解法位于棋盘边界内且覆盖全部格子；
2. 相邻格子必须正交相邻；
3. 解法不重复经过格子，也不穿过墙体；
4. 路标从 1 开始连续编号，并位于解法路径上；
5. 解法最终到达最后一个路标。

### 本地数据键

网页端默认把玩家状态保存在浏览器本地，而不是上传到服务器。清除浏览器站点数据会重置以下记录：

| 键名 | 内容 |
|---|---|
| `forest-trail-web-2400-progress-v1` | 首发题完成进度。 |
| `forest-trail-web-2400-continuations-v1` | 分类首发题耗尽后生成的 seed 续关。 |
| `forest-trail-onboarding-seen-v1` | 新手引导完成或跳过记录。 |

## 关卡编辑器

`/editor` 是为内容管理员准备的内部工作台，不对普通玩家开放。编辑器支持：

- 选择棋盘尺寸和难度；
- 编辑解法、路标、水平墙、垂直墙或擦除单元；
- 对关卡进行即时规则校验；
- 保存草稿、发布版本、查看版本历史、回滚和归档；
- 仅将已发布版本提供给玩家使用。

编辑器依赖登录、管理员权限和数据库服务。进行数据库迁移或发布写入前，应在测试环境审查权限、生成的 SQL 与关卡校验结果。

## 运行与部署注意事项

### 首发题库资源

网页端通过 `client/src/game/launchCatalog.ts` 中定义的静态资源地址加载首发题库。当前地址指向项目托管的静态存储。若要自托管，请将首发目录 JSON 上传至自己的对象存储或静态站点，并相应修改 `LAUNCH_CATALOG_URL`。

### 后端与环境变量

游戏首页的基本游玩流程以静态题库和浏览器本地进度为主。关卡编辑器、登录与数据库能力依赖 Express、tRPC、Drizzle 和 MySQL。部署到独立环境时，不应将密钥写入仓库；请通过部署平台的密钥管理功能配置数据库连接、JWT、OAuth 与应用标识等环境变量。

### GitHub 协作

当前仓库默认分支为 `main`。建议为生产分支启用保护规则，要求类型检查和测试通过后再合并；如果仓库只用于内部备份，请在 GitHub 仓库设置中改为私有可见性。
