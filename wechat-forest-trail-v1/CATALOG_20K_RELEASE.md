# 森林寻径 v1.2：20,000 道原创精品题库发布说明

**作者：Manus AI**  
**题库版本：2.0.0**  
**游戏版本：1.2.0**  
**日期：2026-09-02**

## 1. 发布概要

本版本在原有 2,400 道关卡的基础上新增 **17,600 道原创精品题**，使总量达到 **20,000 道**。参考游戏的 Unlimited 模式公开呈现了 6×6、8×8、10×10、12×12 四种棋盘规格，并将 Easy、Medium、Hard 定义为相对当前规格的难度梯度。[1] 本题库只借鉴这些公开的产品维度、玩法结构和难度理念；所有新增题目均由本工程的确定性路径、墙体和路标生成管线产生，未抓取、复制或复用参考网站的具体题目。

> “精品”在本项目中表示题目具有稳定身份、可复现生成 Seed、有效标准解、有效可见约束、指定难度画像和发布前验证记录；它不表示 8×8 及以上题目已在移动端完成穷举唯一解证明。

## 2. 最终配额

| 棋盘规格 | Easy | Medium | Hard | 小计 |
|---|---:|---:|---:|---:|
| 6×6 | 2,000 | 3,900 | 3,100 | 9,000 |
| 8×8 | 1,500 | 3,300 | 2,200 | 7,000 |
| 10×10 | 600 | 1,400 | 1,000 | 3,000 |
| 12×12 | 300 | 400 | 300 | 1,000 |
| **总计** | **4,400** | **9,000** | **6,600** | **20,000** |

6×6 与 8×8 合计 16,000 道，承担新手、日常无限模式和主力玩家的主要消费；10×10 与 12×12 合计 4,000 道，用于中高阶挑战、渐进模式后段与限时玩法。Medium 占比最高，使主力模式在不显著提高挫败感的情况下拥有足够的持续供给。

## 3. 生成与质量门禁

新增题库采用固定 Seed 驱动的 Hamilton 路径生成，基于路径放置不破坏标准解的墙体，并按照 Easy、Medium、Hard 选择递减的数字路标密度。每题保存标题、稳定 ID、尺寸、难度、Seed、路径、墙体、路标、生成器元数据和难度画像；同一记录可以由同一版本的生成器复现。

| 检查层级 | 应用范围 | 结果 |
|---|---|---|
| 题目规范 | 全部 20,000 道 | 尺寸、路标、墙体、路径和稳定 ID 均通过 |
| 标准解验证 | 全部 20,000 道 | 路径全覆盖、相邻移动、路标顺序和墙体约束均通过 |
| 可见约束去重 | 全部 20,000 道 | 墙体 + 路标构成的可见题面无重复 |
| 唯一解门禁 | 新增 6×6 题 | 全部通过带 250,000 节点预算的求解器唯一解检查；多解候选通过加墙消歧 |
| 大棋盘质量策略 | 8×8–12×12 | 已验证标准解与路径/墙体兼容；发布元数据不声明端侧唯一解证明 |

离线生成的实际构建结果为 17,600 道新增题，生产过程耗时约 493 秒。各难度桶的额外候选重试均已记录在 `catalog/catalog-build-v2-report.json`，便于后续审计与重新生产。

## 4. 运行时交付方式

直接把 20,000 道“展开后的完整对象”放在一个 JavaScript 数组里会造成不适合移动启动阶段的解析成本。测试环境中，48 MB 的展开对象源文件加载约需 4.15 秒并带来约 322 MB 的堆内存增量。因此，发布包改用紧凑分桶交付：启动时只读取约 2.4 KB 的题库清单；当用户选择尺寸和难度后，再加载对应的 12 个规格桶之一，并仅还原当前要玩的完整关卡。

| 指标 | 旧的完整对象数组 | v2 紧凑分桶记录 |
|---|---:|---:|
| 题库规模 | 20,000 道 | 20,000 道 |
| 原始题目表示 | 约 48 MB | 不进入小游戏运行时载荷 |
| 发布记录总大小 | 不适用 | 约 2.62 MB + 约 2.4 KB 清单 |
| 清单加载 | 不适用 | 约 0.82 ms；约 0.05 MB 堆增量 |
| 默认 6×6 Easy 桶加载 | 不适用 | 2,000 条记录；约 5.56 ms；约 0.99 MB 堆增量 |
| 单题还原 | 不适用 | 约 30.05 ms |

上述性能数据在 Node.js 沙箱中测得，仅用于比较发布结构，不能替代 iOS 与 Android 真机验收。紧凑记录分为两类：原有 2,400 道题使用压缩路径/路标索引；新增 17,600 道题保存稳定 ID、标题和 Seed，并在被选中时通过同一管线还原。

## 5. 工程变更

| 位置 | 作用 |
|---|---|
| `catalog/catalogManifest.js` | 轻量元数据、12 个桶的数量和按需加载函数 |
| `catalog/records/*.js` | 尺寸 × 难度的紧凑题目记录 |
| `core/providers/CompactCatalog.js` | 紧凑记录解码、Seed 复现与完整关卡还原 |
| `core/providers/HybridLevelProvider.js` | 精品桶懒加载、48 题已还原缓存、个人防重复和 Seed 兜底 |
| `scripts/build-catalog-v2.cjs` | 离线增量生产与质量门禁 |
| `scripts/compact-catalog-v2.cjs` | 完整题目到发布分桶的压缩过程 |
| `scripts/verify-catalog-source-v2.cjs` | 发布源题、紧凑记录与标准解的一致性检查 |

`game.js` 现在只加载 `catalogManifest`，而不再在开场后加载完整题目数组。若题库分包不可用，现有 Seed 生成兜底仍然允许玩家进入游戏。

## 6. 验证结果

```bash
npm run verify
node scripts/verify-catalog-source-v2.cjs
node test/catalog-load-performance.cjs
```

本次已完成语法、规则引擎、模式、存档、音效、通关粒子、紧凑供应、全量题目 ID 与分桶、抽样还原，以及完整源题与发布记录一致性验证。验证结果为：**20,000 道记录完整、17,600 道新增原创 Seed 题、2,400 道压缩兼容题、12 个分桶配额均符合目标**。

## 7. 真机验收重点

导入微信开发者工具后，应优先在 iOS 与 Android 真机上验证首次启动、6×6 Easy 首题、8×8 Medium 切换、12×12 Hard 切换、重复打开不同尺寸桶、断网/弱网题库分包回退，以及连续进入下一题时的内存情况。正式赛季、排行榜或每日题仍建议使用服务端锁定的题目版本和离线验证 Seed。
